# Sweep author surface — element-wise work and whole-buffer access

C ext authors writing CArray-aware code typically need one of three
things:

1. *element-wise work* over one or more CArrays ("y = sqrt(x)",
   "(lon, lat) -> (x, y) projection", "sum this")
2. *whole contig buffer access* to hand off to a third-party C library
   ("call FFTW on this buffer", "feed this to fitpack's solver")
3. *per-axis work* (reductions, scans, sliding windows)

(1) and (2) are the sweep author surface, both built on the `xfer_all`
primitive. They never call `ca_attach` on a view's ancestor (= no
"ancestor cascade" memory peak), and they pick zero-copy alias when the
source is a contig entity. (3) is the kernel iterator
(`CA_FOR_EACH_SLAB` / `CA_FOR_EACH_FIBER`, `ca_kernel_iterator.h`).

## Element-wise: `ca_call_cfunc_*_r` and `ca_call_cslab_*_r`

Header: `carray.h` (pulls `carray_call_cfunc.h`). The author writes a
callback; the engine acquires the operands, checks that their shapes
pair, ORs the INPUT masks and propagates the result to the OUTPUTs.
The trailing `void *userdata` is handed to every callback invocation
(= POSIX `_r` convention), so the kernel can share state with the
caller (accumulators, configuration, library plan handles) without
file-static plumbing.

`fsync` names each operand's direction, one character per operand:
`'0'` = INPUT, `'1'` = OUTPUT.

### Per cell: `ca_call_cfunc_N_r`

```c
static void
sqrt_cell (void *x, void *y, void *userdata)
{
  *(double *) y = sqrt(*(double *) x);
}

ca_call_cfunc_2_r(sqrt_cell, "01", r_in, r_out, NULL);
```

Masked cells are skipped. The typed dispatchers `ca_call_cfunc_M_N_r`
take the data types the callback works in, cast the inputs to them and
return a freshly allocated output.

### Per chunk: `ca_call_cslab_N_r`

```c
static void
sum_chunk (char **base, ca_size_t *stride, ca_size_t n,
           const boolean8_t *m0, void *userdata)
{
  double *sum = (double *) userdata;
  for (ca_size_t k = 0; k < n; k++) {
    if (m0 && m0[k]) continue;
    *sum += *(double *) (base[0] + k * stride[0]);
  }
}

double sum = 0.0;
ca_call_cslab_1_r(sum_chunk, "0", r_ca, &sum);
```

The callback receives one chunk at a time: a `base` and `stride` per
operand, a cell count, and the chunk's slice of the mask (`NULL` when
no INPUT is masked). A masked cell is the author's to skip. A non-alias
INPUT view (`a[mask]`, `a.transpose`, ...) is re-gathered into a
~32 KB scratch per chunk rather than materialised whole, so the input
memory peak does not scale with the operand, and the indirect call is
paid once per chunk, so the inner loop is one the compiler can
vectorise.

Both families close everything they acquired when the callback raises.

## Whole contig buffer: `rb_ca_call_with_buffer`

Header: `ca_for_buffer.h`.

```c
typedef struct { fftw_plan plan; } ud_t;

static void
fftw_body (void *user_data, void *ptr, ca_size_t n)
{
  ud_t *ud = (ud_t *) user_data;
  fftw_execute_dft(ud->plan, ptr, ptr);
}

static VALUE
fftw_inplace_pass (VALUE self, VALUE r_in)
{
  ud_t ud = { /* plan = ... */ };
  rb_ca_call_with_buffer(r_in, /*writable=*/1, fftw_body, &ud);
  return r_in;
}
```

`ptr` is `ca->ptr` itself when the array is a contig entity (zero
copy), and a materialised contig buffer when it is a view. A writable
call writes the buffer back to the view's storage when the body
returns, so writes through a slice view land in the parent.

The body may raise. The array is closed however the body is left: a
writable array is still written back, so partial writes propagate, then
detached (even if the write-back raises), and the exception continues
to unwind. Return a result through `user_data`.

Compared with calling `ca_attach` / `ca_sync_detach` yourself, this is
the form that cannot leave the array attached: a raise between a
hand-written attach and detach skips the detach.

## What's not here

- **Per-axis kernels** (reductions, scans, sliding windows): use the
  `CA_FOR_EACH_SLAB` / `CA_FOR_EACH_FIBER` families
  (`ca_kernel_iterator.h`).
- **Profile-driven chunk size tuning**: the chunk target is `4096`
  elements (~32 KB at f64) by default. Replace at the engine level
  (`ca_chunk_compute_n`) if you measure something better for a
  specific data type mix.
